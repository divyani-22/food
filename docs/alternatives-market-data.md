# Alternatives: real price and availability data

The scan result page shows a "Where to find it" block inside each healthier-alternative card. Everything in it comes
from two public, crowd-sourced sources. Nothing is generated by the LLM and nothing is invented.

> **STATUS: live behaviour is UNVERIFIED.** The build sandbox could not reach `openfoodfacts.org` or
> `prices.openfoodfacts.org` (curl returned 000). The integration was written against the documented response shapes and
> tested only against a local stub that imitates those shapes (`server/altMarket*.test.ts`, `e2e/alt-market.mjs`).
> Do a manual smoke test against the real hosts before relying on it.

## Sources

| Source | Used for | Config |
| --- | --- | --- |
| Open Food Facts search (`/cgi/search.pl`, `json=1`) | product code, brands, `stores`, `countries_tags`, `nutriscore_grade`, `image_front_small_url` | `OPENFOODFACTS_BASE_URL` (existing) |
| Open Prices (`/api/v1/prices?product_code=<code>&order_by=-date&size=20`) | community-reported prices (price, currency, date, location) | `OPEN_PRICES_BASE_URL` (site origin, default `https://prices.openfoodfacts.org`) |

## Flow

`analysis.alternativeMarket({ scanId })` (tRPC query, logged-in user, scan must be owned, else `NOT_FOUND`):

1. For each alternative (max 8) build the query `brand + productName`.
2. Search OFF. If the profile `region` maps to a known country (small built-in list), the search is restricted to that country; otherwise it is worldwide.
3. `matchProduct` accepts a candidate only if it passes a conservative rule: brand known -> the brand must match (all tokens, any entry of OFF's comma-separated brand list) and name token coverage >= 60% and precision >= 40%; brand unknown -> coverage >= 80%, precision >= 60%, 2+ shared tokens. Otherwise `status: "no_match"` and the UI says "No community data found".
4. For a match, fetch Open Prices for the code. The newest price is shown, preferring prices recorded in the user's country. Min/max/count cover prices in the same currency (and same `price_per`) within 180 days of the newest. Currencies are never converted. A price older than 12 months is flagged "Old price".
5. Stores = OFF `stores` plus the locations of the community price reports (max 10 returned, 5 shown as chips).

Result per alternative: `{ alternativeId, status: "ok"|"no_match"|"unavailable", match, availability:{stores,countries}, price, priceStatus }`.
Any network/parse failure gives `status: "unavailable"` (or `priceStatus: "unavailable"` when only prices failed); the procedure never throws for upstream problems.

## Safety and limits

- Only the two configured hosts, http/https only, origin re-checked, redirects refused, 6 s timeout, 1 MB response cap, max 3 outbound requests in flight.
- Per-user rate limit on the procedure: 20 calls/minute (`TOO_MANY_REQUESTS`).
- In-memory LRU caches (500 entries each) for search and prices, 6 h TTL (`ALT_MARKET_CACHE_TTL_SECONDS` overrides); disabled when `OFF_CACHE_DISABLED=true` and under `NODE_ENV=test`. Failures are never cached. Nothing is stored in the database (no schema change); restarts clear the cache.
- The UI loads lazily: only when the scan has alternatives and the list is near the viewport.
